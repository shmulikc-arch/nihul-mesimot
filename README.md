# מוקד תקלות - הוראות הפעלה

מערכת דיווח וניהול תקלות לבית ספר: מורות מדווחות, ושלושה גורמים (אב בית /
אחראי מחשבים / מזכירות) מטפלים כל אחד בתקלות שמשויכות אליו, בתוספת דשבורד
ראשי שמרכז הכל. הקוד הוא HTML/CSS/JS רגיל (בלי שלב build), עם Firebase
כבאקנד - בדיוק כמו יומן הנוכחות.

## מבנה הקבצים

```
index.html          - מסך התחברות
report.html          - מסך דיווח (למורות, ולכל צוות שרוצה לדווח)
facilities.html      - דשבורד אב בית
it.html              - דשבורד אחראי מחשבים
secretary.html       - דשבורד מזכירות
admin.html           - דשבורד ראשי (מנהל מערכת)
css/style.css        - עיצוב משותף (רספונסיבי - טלפון ומחשב)
js/firebase-config.js- כאן מדביקים את פרטי החיבור לפרויקט הפיירבייס שלכם
js/auth.js           - הרשאות והתחברות (משותף)
js/dashboard.js       - הלוגיקה המשותפת לשלושת הדשבורדים
manifest.json + icons/ - תמיכה ב"הוספה למסך הבית" בטלפון
firestore.rules      - חוקי אבטחה למסד הנתונים (להדביק בקונסולה)
storage.rules         - חוקי אבטחה לתמונות (להדביק בקונסולה)
```

## שלב 1: פתיחת פרויקט חדש בפיירבייס

1. כנסו ל-console.firebase.google.com עם אותו חשבון Google שכבר יש לכם
   (זה שבו בנוי פרויקט יומן הנוכחות) ולחצו "Add project" / "הוספת פרויקט".
2. תנו לו שם, לדוגמה **מוקד תקלות**. אין צורך ב-Google Analytics - אפשר לכבות.
3. בתוך הפרויקט החדש, במסך הראשי, לחצו על סמל ה-**`</>`** (הוספת אפליקציית
   ווב), תנו לה כינוי (למשל "אתר"), ואל תסמנו Firebase Hosting (לא נשתמש
   בו - נשתמש ב-GitHub Pages). בסיום תופיע בלוק קוד שנקרא `firebaseConfig` -
   **העתיקו את הערכים משם** לתוך הקובץ `js/firebase-config.js`, במקום
   ה-`"REPLACE_ME"`.

## שלב 2: הפעלת Authentication

1. בתפריט הצד: **Build -> Authentication -> Get started**.
2. בלשונית **Sign-in method**, הפעילו את הספק **Email/Password** (הראשון
   ברשימה) ושמרו.

## שלב 3: הפעלת Firestore (מסד הנתונים)

1. בתפריט הצד: **Build -> Firestore Database -> Create database**.
2. בחרו מיקום (Location) - כל מיקום קרוב באירופה מתאים (לדוגמה
   `eur3` / `europe-west1`). **לא ניתן לשנות מיקום אחרי היצירה**, אבל
   זה לא משנה בפועל לשימוש של בית ספר בודד.
3. בחרו **Start in production mode**.
4. אחרי היצירה, לכו ללשונית **Rules**, מחקו את מה שכתוב שם, והדביקו
   בדיוק את התוכן של הקובץ `firestore.rules` מהתיקייה הזו. לחצו **Publish**.

## שלב 4: הפעלת Storage (לתמונות התקלות) - שימו לב, שלב אופציונלי

תמיכה בצירוף תמונה לדיווח דורשת הפעלת Storage, וזה דורש שדרוג לתוכנית
**Blaze** (תשלום-לפי-שימוש) - כולל חיבור כרטיס אשראי לחשבון Google Cloud.
בהיקף שימוש של בית ספר בודד, כמעט בוודאות **לא יהיה חיוב בפועל** (יש מכסה
חינמית נדיבה גם ב-Blaze) - אבל כרטיס אשראי כן נדרש כדי להפעיל בכלל.

- **אם אתם מוכנים לזה עכשיו:** Build -> Storage -> Get started -> שדרגו
  לתוכנית Blaze כשתתבקשו -> אחרי ההפעלה, בלשונית Rules הדביקו את התוכן
  של `storage.rules` ולחצו Publish.
- **אם אתם מעדיפים לדחות את זה:** אין שום בעיה - כל שאר המערכת (דיווח
  טקסטואלי, שלושת הדשבורדים, הדשבורד הראשי) עובדת מצוין גם בלי זה.
  פשוט אל תלחצו על "הוספת תמונה" במסך הדיווח בינתיים (אם ילחצו, הדיווח
  יכשל עם שגיאה, כי הגיבוי ל-Storage לא יהיה זמין). אפשר להפעיל את זה
  בכל שלב מאוחר יותר.

## שלב 5: יצירת המשתמשים הראשונים

אין הרשמה עצמית במערכת (בכוונה - כדי שרק צוות בית הספר ייכנס). כל
משתמש נוצר ידנית על ידכם:

1. **Authentication -> Users -> Add user** - הזינו אימייל וסיסמה
   זמנית עבור אותו איש/אשת צוות. אחרי היצירה, **העתיקו את ה-User UID**
   שמופיע לידו ברשימה (מחרוזת אותיות ומספרים ארוכה).
2. **Firestore Database -> Data**, צרו collection בשם **`users`**
   (אם עדיין אין), ובתוכה מסמך חדש שה-**Document ID** שלו הוא **בדיוק**
   ה-UID שהעתקתם. הוסיפו לו שני שדות:
   - `name` (מסוג string) - השם המלא להצגה, למשל "רותי לוי"
   - `role` (מסוג string) - אחד מהערכים הבאים בדיוק:

     | תפקיד | ערך לשדה role |
     |---|---|
     | מורה (מדווחת בלבד) | `teacher` |
     | אב בית | `facilities` |
     | אחראי מחשבים | `it` |
     | מזכירה | `secretary` |
     | מנהל מערכת (הדשבורד הראשי) | `admin` |

3. חזרו על זה לכל איש צוות. בהתחברות, כל אחד יופנה אוטומטית למסך
   המתאים לתפקיד שלו.

## שלב 6: העלאה לגיטהאב + הפעלת GitHub Pages

1. צרו ריפו חדש בגיטהאב (למשל `moked-taklot`), והעלו אליו את **כל**
   הקבצים מהתיקייה הזו (כולל התיקיות `css`, `js`, `icons`) - בדיוק כמו
   שעשיתם עם yomanmorot.
2. בריפו: **Settings -> Pages**. תחת Source בחרו **Deploy from a
   branch**, Branch: **main**, Folder: **/ (root)**, ולחצו **Save**.
3. אחרי דקה-שתיים יופיע למעלה קישור בסגנון
   `https://<שם-המשתמש-שלכם>.github.io/moked-taklot/` - זה הקישור החי.

## בדיקה ראשונה

היכנסו לקישור עם אחד המשתמשים שיצרתם. אמורים להיות מופנים אוטומטית
למסך המתאים לתפקיד שלו. נסו לדווח תקלה כ"מורה", ואז להיכנס עם משתמש
של אחד הגורמים כדי לראות שהיא מופיעה אצלו ולסמן אותה כ"בטיפול"/"טופל".

## הוספה למסך הבית בטלפון

בדפדפן בטלפון (כרום/ספארי), אחרי כניסה לקישור - תפריט הדפדפן ->
"הוספה למסך הבית" (Add to Home Screen). יופיע אייקון רגיל, וזה ייפתח
במסך מלא בלי סרגל כתובת.

## עדכון המערכת בעתיד

כל שינוי בקבצים + `git push` לריפו - GitHub Pages יעדכן את האתר החי
תוך דקה-שתיים, אוטומטית, בלי צורך בשום פעולה נוספת.
